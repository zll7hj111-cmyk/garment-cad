## 1. 背景

原属性面板分四节（基本 / 几何 / 连接 / 端点），**分区依据是"数据存在哪"，不是"用户要回答什么"**。结果：

- 几何、连接、端点三节其实都在答同一个问题——**这条线摆在哪**，逼用户上下翻三遍；
- 「连接」名下混着 5 套互不相干的机制（起点 attachment / 终点 endTarget / 桥接线 isBridge / 组件连接 / 省道）；
- 低频项（延长、曲线、滑轨、影子）常显，主界面被稀释。

## 2. 设计原则

**按"用户要回答什么问题"分节，不按"数据结构怎样"分节。**

用户打开属性面板，脑子里只有三个问题：

1. 这条线**是什么**（叫什么、长什么样）
2. 这条线**摆在哪**（两端、长度、角度、跟谁连）
3. 还有**什么边角**（延长、曲线、注释、特殊模式）

对应的三节：**本线 / 摆放 / 按需组**。

## 5. 连接三态与互斥规则

### 5.1 三态

每个端点可处于三种状态之一：

- **连接** —— 端点钉在目标点上（真连接，消耗位置自由度）
- **指向** —— 端点只朝目标方向，不钉位置（消耗旋转自由度）
- **拆开** —— 自由

### 5.2 自由度核算（一条线只有 4 个：位置 X、Y、旋转、长度）

> 修正（2026-xx）：原表把「自由」端点记 1 DOF 且漏算角度约束，导致「连 自由 指定」误判为 ✅。实际「自由」端点贡献 0 DOF（其位置是自由变量），「连 自由」必须**长度 + 角度**同时指定才满 4 DOF（与 §5.3 规则 5 一致）。

| 点A | 点B | 长度 | 角度 | 合计 | 判定 |
| -- | -- | ------ | -- | --------- | --------- |
| 连  | 连  | 自动 | —    | 2+2 = 4   | ✅ 桥接线     |
| 连  | 连  | **指定** | — | 2+2+1 = 5 | ❌ **超定**  |
| 连  | 指向 | 指定 | 禁用 | 2+1+1 = 4 | ✅         |
| 连  | 指向 | 自动 | 禁用 | 2+1 = 3   | ❌ 欠定      |
| 连  | 自由 | 指定 | 生效 | 2+0+1+1 = 4 | ✅ 普通连接线 |
| 连  | 自由 | 自动 | 生效 | 2+0+0+1 = 3 | ❌ 欠定      |
| 自由 | 自由 | —    | —    | —         | 独立线（另行处理） |

### 5.3 由此推出的 UI 规则

1. **两点都连接 → 长度强制自动**（只读回显两点距离，"指定"灰掉）。再指定就超定，几何上无解。
2. **只有一点连接时，另一个才允许「指向」**。
3. **指向时长度必须指定**（否则欠定）。
4. **指向时角度禁用** —— 旋转已被指向占用，改角度会超定。提示："指向中，角度由指向决定；取消指向后可改"。
5. **只有一点连接 + 另一点自由 → 长度必须指定，角度基准生效**。

## 6. 关键设计决策

### 6.1 端点组按创建序固定（2026-08-31 三轮拍板；终版语义见下方补充）

**线段没有真正的起点终点** —— 语义可换（`ReverseSegmentCommand` 本来就能换），决定方向的是 点1 → 点2。

配套的 **朝向箭头**画在两个端点组之间，点击只翻转箭头方向。

> **定版规则（2026-08-31 三轮用户拍板）**：**上组恒 = 先画的起点（start），下组恒 = 后画的终点（end）**，不随几何位置/世界朝向翻转。理由：用户是"按创建顺序"谈论一条线的（先点哪儿、后点哪儿），几何翻转反而制造"凭空洗牌"感。点击箭头（换向 = 物理换身）后，上下两组**内容随之互换**（start/end 身份换位），但"上=先画、下=后画"的语义恒定；箭头方向 = start→end 世界朝向（↓ = 起点在上、↑ = 终点在上），换向后只翻箭头。
> 延长量/摘要灰字恒按 start/end 角色（= 创建序）归属；**「连接到」行按维度归属**（跟随行 = Attachment、指向行 = endTarget，维度行非点行，不随箭头翻转）。
> 演进记录：一版"内容互换（点 ID 当组标题）"→ 二版"组按几何位置固定"（用户问"为什么小数在下面"）→ 三版"按创建序固定"（换向后仍内容互换，用户指出箭头已是方向指示器、双重翻转毫无必要）→ **终版"槽位固定 + 箭头指示器"（见下）**。

> **终版规则（2026-08-31 第四轮用户拍板，覆盖上方规则中"内容随之互换"的表述）**：**槽位本身永不交换** —— 上槽恒显示模型 start 端、下槽恒显示 end 端，控件布局是死的，"P1 上/P2 下"的相对关系恒定。点朝向箭头 = `ReverseSegmentCommand` 物理换身（start 改指另一个物理点），populate 仍读 start 回填上槽 → 上槽内容自然换成新的 start 点，**无需任何交换/翻转代码**。**箭头 = 纯朝向指示器**：方向 = start→end 世界朝向投影（↓ = 当前起点在画布偏上方一侧；↑ = 反之），点击后模型换向 → 只见箭头翻面 —— 用户原话："只要改变箭头的方向就好了，箭头的方向就是指示器。" UI 无自有状态、只是模型的投影。

### 6.2 延长归端点组

延长本来就是端点的事（起点延长 / 终点延长）。原先放在面板底部单独一节是错位的。

### 6.3 长度是枢纽

- **自动** = 两头钉死，长度算出来（桥接行为）
- **指定** = 起点钉死，按角度延伸

用它一个开关取代了原先独立的「落点方式（桥接落点/仅指向）」两个概念 —— **概念消灭，不是改名**。

### 6.4 "基准"降级为"相对"，默认自动

"基准"对新手是抽象词。它九成情况下就是"你连上的那条线"，不该暴露成必填项。

**基准有三态**，由 [独立] 按钮切换：

| 状态 | 点1/点2 | 角度相对谁 | 何时用 |
|---|---|---|---|
| **自动**（默认） | 空（灰显回显所连的线） | 跟随所连的那条线 | 九成场景，不用碰 |
| **自定义** | 填入两个点 | 点1→点2 的连线方向 | 想让这条线对齐"任意两点连线" |
| **独立** | 清空 | **世界角度**（绝对坐标系） | 不跟任何线，自己定绝对角度 |

[独立] 按钮点击 = 清空点1/点2 切到世界角度；再点击 = 还原上次填入的内容（**只缓存一份**，不保留历史）。

**关键扩展**：点1/点2 是**任意两个点**，不再是"基准线段 + 基准线段上的点"。两点连线即方向，表达能力比原来强（原来只能对齐某条线段的出口方向）。

**对齐锚点 [P1]**：两点定出方向后，还要回答"这条线的哪个点去对齐它"——答案是**朝向起点**（随朝向箭头翻转）。所以完整句式是：

> `[P1] 以点1【p4】到点2【p5】的方向为角度基准`

### 6.5 便利贴控件（NoteButton）

长文本注释收进悬浮便利贴，替代超长单行输入框。**控件不碰模型、不推 undo**，只发 `noteEdited(text)`，提交时机交给宿主——这是它能一处实现、多处复用的前提。

已接入：本线名称、P1、P2。后续推广：`FormulaVariable::comment`、`AngleMeasureVariable::comment`。

### 6.6 名称复用

连接框既能输**名字**也能输**编号**（"肩点" 或 P7 都认），省掉"记编号"这件事。

## 7. 手势动作与字段自动填入

**核心原则：输入框由手势自动填入，用户不必手动填。** 手动输入（P# 或名字）只是补充手段——用于手势够不着的情况。

### 7.1 画新线（智能笔）

| 手势 | 代码 | 连接框 | 角度基准 | 长度 |
|---|---|---|---|---|
| 两端都不吸附 | `LineFactory::createFreeLine` | 空 | 空 → 世界角度 | 指定 |
| 起点吸附、终点自由 | `createAttachedLine` | 起点 = 吸附点 | 自动（跟随所连的线） | 指定 |
| 两端都吸附 | `createBridgeLine` | 两端都填 | 空（方向已由两点决定） | 自动（= 两点距离） |
| 省道 | `createDartLine` | 移出面板 | — | — |

新建连接时一律**反算 followerAngle**（`backSolveFollowerAngle`）——用当前朝向倒推出角度值，所以接上的瞬间线不会跳。

### 7.2 拖动（ToolSelect → ConnectGesture）

| 手势 | 代码 | 填入行为 |
|---|---|---|
| 拖动选中线段的端点到别的点 | `beginConnect` → `attachToTarget` | 该端点连接框 = 目标点；基准 = 自动；反算角度不跳变 |
| 拖动**已拆开**（位置自由）线的端点 | `reattachAngleOnly` | **原地重挂原连接，不新建**（森林不变式：一块至多一条跟随连接）。旧角度基准自动转成"自定义"——点1/点2 = 旧目标点及其所在线段。**这是「点1/点2 可为任意两点」最典型的用武之地**：老模型只能对齐"某条线段的出口方向"，表达不了这种跨线段的基准 |
| 拖动组件端点 | `attachToTarget`（组件分支） | 组件级连接，整组刚体跟随 |
| 组件重叠切换 | `switchComponentTarget` | 换跟随的基准线段 |

### 7.3 其它自动路径

| 操作 | 代码 | 填入行为 |
|---|---|---|
| 打断线 | `BreakCommands:1213` | 断口两端的连接按打断规则重建 |
| 旋转复制 | `RotateCopyGesture:85/180` | **克隆**原连接的整组关系（连接 + 基准 + 长度模式） |
| 复制拖拽 | `CopyDragController` | 按复制语义保持或断开（细节待确认） |
| 面板输入 P# / 名字 | `SegmentConnectionCard` | 手动建立/重定向，与拖拽**同规则**：同样反算角度、同样过互斥检查 |

### 7.4 一句话总结

**手势负责"填"，面板负责"改"。** 用户画完线，框里已经有内容了；打开面板只是要微调或确认，不是从零填表。

## 9. 实施风险

1. **Resolver 需重写优先级**：现有 `preserveEndTargetRotation`（`Resolver.cpp:796`）偷偷让 endTarget 覆盖 attachment 的旋转。新模型要把它变成显式规则。
2. **环检测**：端点级放宽后可能出现以往不可能的环，建议保守维持 Block 级检测。
3. **老档迁移**：`Block::endTarget*` 四字段需迁移为新模型；`isBridge` / `isPin` 已无生产路径，可删（Resolver Step 4/5 随之）。
4. **省道移出**需确认它在哪里落脚。

### 10.7 四个必须避开的坑

1. **ElaText 的 `setStyleSheet` 必须带 `background: transparent`** —— `setStyleSheet` 会整体替换 ElaText 构造器的 `#ElaText{background-color:transparent}` 规则，漏了标题就变不透明浅底、细笔画抗锯齿糊成灰。
2. **`accentBar` / `divider` 的样式走全局 QSS** —— 代码里只设 `objectName`，不要在代码里画样式，否则明暗双模失效。
3. **新控件只加进 `CMakeLists.txt` 的模块库**（UI 归 `gcad_ui`），**不要**加进测试/可执行目标的源列表——AUTOMOC 会重复 moc 导致 LNK2005。
4. **改了被广泛包含的头文件**（如 `parametric/Segment.h`）**后测试若出现零输出段错误，是 stale object**，三件套同删才有效：`<t>.dir` + `<t>_autogen.dir` + exe（详见 TROUBLESHOOTING 第 1 组）。只删 `.dir` 没用。
